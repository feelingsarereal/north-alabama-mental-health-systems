# North Alabama Mental Health Systems Report — draft for review

A public, searchable, interactive edition of the *North Alabama Mental Health Systems Report* (**Little Orange Fish, prepared with Claude**): the regional companion to the statewide [Alabama Mental Health Systems Report](https://feelingsarereal.github.io/alabama-mental-health-systems/). It describes the mental health system in Madison and Cullman counties, which are WellStone's service area, and the fifteen-county catchment of the Huntsville crisis center. The report was researched and written for this site from public sources, and every sentence was read back against the passage that supports it. Generated by the Manuscript Interrogator (builder 0.5.2) from `content-pack/`, `mode: topic`.

The site has five jobs: **read the report** with the source of every sentence one hover away (1,497 claims, 978 verified against a quoted passage); **see what could not be settled** (129 open items); **explore the region on two maps** (15 counties, 36 layers; 117 census tracts of Madison and Cullman, 28 layers, with 54 service locations); **explore the system as a graph** (13 parts, the report's 11 dependencies); **learn the ideas** (12 primers, 189 glossary terms).

## This is a draft for review

- The report has **not been approved** by Little Orange Fish and is **not peer reviewed**. It is **independent of WellStone** and of every organization it describes: none supplied material, saw the text or endorsed it. It is not a position of the North Alabama Mental Health Coalition or any of its members, and it contains no clinical guidance.
- What could not be read, confirmed or found is on `/open-items` (the first 22 are the report's Appendix C).
- A banner on every route says so and cannot be dismissed. `manifest.venue` is on `/` and `/about`; the `as_of` date (4 October 2026) is on `/`, `/read`, `/about`, both maps and `/systems`.
- Errors: open an issue with the **Report an error** template (page or block id, what is wrong, the source that shows it).

## Quick start

Double-click **`App Shortcuts/▶ Open North Alabama Mental Health Explorer.command`** (made by the Cowork project). It installs on first run, rebuilds when something changed, and opens **http://localhost:4189/**.

By hand:

```bash
npm ci
npm run build:content      # validate content-pack/, emit src/data/*.json + public/provenance.json
npm run build              # tsc + vite → dist/ (BASE_PATH=/repo/ for GitHub Pages)
npm run preview -- --port 4189 --strictPort
npm test                   # Vitest
npm run test:e2e           # Playwright against dist/ on :4173 (BX_PORT=… if that port is taken)
```

`npm run build:geometry` is a **one-time** step that downloads the Census Bureau's tract boundary file and writes `public/data/geo/tracts-madison-cullman.topo.json`, which is committed. Neither `npm run build` nor CI needs the network.

## Editing the content pack

`content-pack/` is the only source of content. The loop:

1. Edit a pack file (`review.md`, `claims-ledger.yaml`, `open-items.yaml`, `references.yaml`, `glossary.yaml`, `concepts/*.md`, `geo/*`, `systems/indicators.json`, `figures/data/*`).
2. `npm run build:content`. It validates every file (zod schemas in `scripts/lib/schemas.ts`), parses `review.md` into blocks, links citations and glossary terms, anchors every ledger claim, indexes the open items, builds both maps and the graph, builds the search index, and prints a summary table. Any error is listed, written to `content-pack/BUILD-ERRORS.md`, shown on `/methods`, and the command exits non-zero — whatever validated is still emitted. The pack as delivered builds with **0 errors**.
3. `npm run build && npm run preview`, check, commit `content-pack/` and `src/data/` together.

### Rules the build enforces

- **Uncited prose fails** (APP-SPEC §6.1): any block of 25+ words with no `[n]` and no `<!-- framing -->`, in `review.md`, in a primer, or in a glossary definition (except the two terms marked `self_description`). A primer paragraph may *open* with its marker (`<!-- framing --> Domain 1 describes…`); the build moves it to the end of the paragraph before parsing, so CommonMark does not read the line as raw HTML.
- **Block ids**: every paragraph and list item ends `<!-- b: B0123 -->` (markers before it); a table has its id on the line above. Appendix C's three lists carry one id each, on the last item, and are read as one block of kind `list` (B0280–B0282); each of their 22 items links to its open item. Figure markers are slots, not blocks.
- **Claim anchors** (KICKOFF §4b): a ledger `quote` must match exactly once in its block's rendered text after normalising emphasis, comments and whitespace; ` | ` lists fragments of one table row. Zero or several matches is a build error, never re-pointed. All 1,497 anchor.
- **Maps** (KICKOFF §4d): every CSV column has a layer and every layer a column; layer ids are unique **within a geography** (nine ids, such as `pct_poverty`, exist at both county and tract level, so a layer's key is `county:pct_poverty` / `tract:pct_poverty`); every FIPS code and tract id has geometry; a survey tract estimate must have its margin of error; empty cells are missing values, never zero.
- **Systems graph**: node, edge, block, indicator and layer ids must resolve; the fan-out row has one source node.

## How it is built

- Ported from the statewide app (K7, `../alabama-mental-health-systems`), minus `/changes` and `/map/us`, plus a tract map with margins of error and a service-location layer.
- Vite + React 18 + TypeScript (strict) + Tailwind 3; react-router 6; Recharts for the charts; MiniSearch for search; Carlito self-hosted via `@fontsource/carlito`.
- **Geometry is projected at build time** into SVG path strings (`scripts/lib/geo.ts`): the fifteen counties from `us-atlas` (the rest of Alabama as one muted backdrop path), and the 117 tracts from the committed Census Bureau file, each county fitted to its own frame. Service locations are projected with the same projections; places that share a coordinate (WellStone's Huntsville campus) become one marker that lists all of them. The browser ships no projection code and fetches nothing.
- The reader's text is compact hast built at content-build time (`scripts/lib/review.ts`): citations, terms and claims are matched on **rendered text**. One delegated popover layer (`src/components/HoverLayer.tsx`) serves every citation, term and claim.
- The notepad is ported from K7 (itself from `ptsd-inflammation-critique` at `afb9dab`, APP-SPEC §3.1): localStorage keyed by `north-alabama-mental-health-systems`; anchors on sections, blocks, terms, references, figures, open items, map selections (`region|tracts:layer:FIPS or tract id`), service locations and graph nodes; under `npm run dev`/`preview` on localhost an autosave to `notes/notepad.md`.
- Performance: the report data is split in two chunks; both map routes and their geometry are code-split; a small build plugin (`vite.config.ts`, `routePreload`) preloads the current route's chunks. Lighthouse (mobile, simulated throttling, local preview, 4 Oct 2026): `/read` 93 / accessibility 100; `/map/tracts` 91 / 100; `/systems` 93 / 100; `/map/region` 88 / 100; `/figures/fig-served` 88 / 100; `/` 95 / 100.

The map ramp is one sequential ramp built from the brand orange. The logo is used as supplied (on a white rounded panel in dark mode); the favicon is the fish mark cropped from the supplied image.

## Provenance

- Every sentence, definition, summary, number and label comes from `content-pack/`. Gaps render as amber `TODO(author)` markers and list on `/methods`.
- The report's text is rendered as written. Passages marked `<!-- synthesis -->` (59) carry the label **analysis** and are listed on `/methods`; `<!-- framing -->` passages carry no claim of fact.
- The maps show values as published. The only computations are the five-class quantile breaks (d3 `scaleQuantile`) over the published values of that map, an area's position in the ordered list ("3rd highest of 15"), and for a survey tract value the interval estimate − margin to estimate + margin, clipped to 0 and (for percentages) 100 — each labelled "computed from the published values". A tract estimate is never shown without its margin of error; a modeled estimate is always labelled modeled; an approximate marker is drawn hollow and labelled.
- **Tract geometry:** `https://www2.census.gov/geo/tiger/GENZ2023/shp/cb_2023_01_tract_500k.zip`, downloaded 4 October 2026, 1,651,401 bytes (dated 16 April 2024 on the Bureau's server), SHA-256 `f1888d5c64a98e3bbb54ab5f87e0fc040e27f63b1ab8377e1b3b76b248b4841f`; the 117 tracts of counties 089 and 043, checked against `tracts.csv` as a set. Record: `public/data/geo/raw/tract_geometry.json`.
- `public/provenance.json` holds the build's counts.
